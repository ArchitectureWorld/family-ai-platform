# 管理员音箱监测与现网基线归并

## 功能边界

Family Admin 的「设备」页统一展示 DIY N16R8、ESP32-S3 BOX-3、微雪音频板的状态。Linux 独立采集器读取设备台账、系统服务和语音心跳，原子发布白名单 JSON；Gateway 使用现有 Family Admin Entry 和家庭范围鉴权后提供 `GET /api/v1/admin/speakers`。

观测记录不是认证 Device，不自动配对、复制成员或发放令牌。API 不传递音频、转写、声纹成员、对话内容、凭据、原始错误及主机私有路径。页面区分 USB 插入、Wi-Fi 连接、语音阶段和采集过期；5秒刷新，30秒后去除正常状态，离开页面和授权失效会清理旧数据。

DIY 保持 V4、16kHz录音/48kHz播放、无AEC；BOX-3和微雪保持V5。主机语音服务逐台隔离，硬件与采集器由独立智能音箱工程维护，Gateway仍为家庭业务和权限的唯一权威。

## 配置

同时设置以下两项，缺一会拒绝启动：

```text
FAMILY_AI_SPEAKER_MONITOR_FILE=/run/speaker-monitor/snapshot.json
FAMILY_AI_SPEAKER_MONITOR_FAMILY_REF=<已有家庭引用>
```

容器须只读挂载整个脱敏快照目录，不能单独绑定文件，否则原子替换可能留下旧inode。不要挂载原始语音状态目录、Docker socket或主机凭据目录。采集目录与文件使用0700/0600，并匹配Gateway的数值UID。配置路径不由HTTP参数指定。

状态文件限制64KiB、32台设备；错误格式、重复ID和异常未来时间返回不可用。运行心跳需匹配当前服务PID和实际设备ID。具体故障码经过白名单校验，身份不匹配和心跳过期不会被通用错误覆盖。

## 基线及恢复

此次归并纳入现网Schema15的Family Agent Authority代码及本地主分支独有设计文档，保留原工作区未提交修改。旧Schema9镜像不得打开Schema15库。原部署镜像缺少正式封存材料，因此新候选必须通过官方构建和封存验证。

归并修复了原基线的三处质量问题：Hermes桥接只接受一个有界stdin请求；配置与会话存储跟随已授权且按Profile限定的Hermes Home；两个fast-uri依赖升级到兼容安全补丁。桥接测试使用临时配置及假网络响应，不调用真实Provider。

数据库恢复使用既有V15保护工具，关键恢复源码与原部署保持一致。先停止精确Family实例，保存完整离线数据、原镜像和启动配置，另建演练副本；副本通过后再恢复现场，不手工删除WAL/SHM或重建数据库。具体步骤沿用 [WAL恢复流程](2026-08-30-gateway-wal-recovery.md)。

构建时完整进程崩溃测试在最大2GiB的临时内存目录执行；它验证子进程SIGKILL后的文件、锁和恢复状态机，不宣称磁盘掉电耐久性。运行镜像不带此挂载；独立Docker磁盘卷恢复门禁和现场磁盘副本演练仍保留。
